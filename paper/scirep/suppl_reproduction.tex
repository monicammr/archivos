\snote{repro}

All programs, results and formal proofs of this work are collected in a reproducibility package (folder \texttt{reproducibility/} of the repository \url{https://github.com/monicammr/archivos}, archived on Zenodo, DOI \href{https://doi.org/\zenododoi}{\nolinkurl{\zenododoi}}). Its file \texttt{README.md} is a step-by-step manual; this note summarises what can be checked and how.

\subsection*{Contents of the package}
\begin{itemize}\itemsep0pt
\item \texttt{analysis/}: the method and every numerical analysis of the paper in Python (simulation of the measured outputs of a PEtab problem, selection, external and nested validation, synthetic experiment, robustness, single-parameter subsets, settings, cost, simulator check, comparison with other criteria, identifiability), including the additional analyses described in the Supplementary Notes on robustness (independent directions), on the synthetic experiment (true signal and other amplitudes), on the method settings (error in units of the noise) and on random scenarios and large problems; all settings and seeds are in \texttt{analysis/config.py}.
\item \texttt{results/}: the results of these analyses, one file per benchmark problem, with a data dictionary (\texttt{DATA\_DICTIONARY.md}).
\item \texttt{figures\_tables/}: the programs that produce every figure, table and Supplementary Note that contains numbers from those results.
\item \texttt{lean\_proofs/}: the Lean~4 development (32 modules, 309 theorems and lemmas, 28 benchmark models, and the non-vacuity witnesses \texttt{NonVacuity.lean}).
\item \texttt{lean\_translation/}: the translator of the SBML models into Lean and the independent check of the translation.
\end{itemize}
The PEtab problems are downloaded from the benchmark collection at commit \texttt{fcbddf1} by \texttt{scripts/get\_benchmark.sh}.

\subsection*{Three levels of checking}
The package can be checked at three levels, which answer different questions and are independent of each other: a reader can carry out any one of them without the others.

\emph{Level A: do the figures, tables and numbers of the paper follow from the stored results?} The command \texttt{python figures\_tables/build\_all.py} reads the result files of \texttt{results/} (one per problem and analysis) and regenerates every figure, Table~1, Table~2 and every Supplementary Table and Note that contains numbers; each program also prints the counts quoted in the text (for example the number of admissible problems), so that they can be compared with the paper. No simulation is run. The README contains a table that relates every figure, table and number of the paper to the program that produces it and to the result files it reads, and \texttt{DATA\_DICTIONARY.md} explains every field of those files. This level shows that nothing in the paper was typed by hand or taken from elsewhere than the stored results; it does not show that the results themselves are correct, which is the purpose of level~C. It takes a few minutes on a laptop and needs Python and a \LaTeX\ distribution.

\emph{Level B: are the mathematical statements proved, and do they assume nothing unproved?} The command \texttt{./verify.sh} in \texttt{lean\_proofs/} compiles the whole Lean development (32 theory modules with 309 theorems and lemmas, the non-vacuity witnesses and the 28 benchmark models) from scratch and stops with an error unless (i) no file contains \texttt{sorry} or an \texttt{axiom} declaration, (ii) every proof is accepted by the Lean kernel and (iii) every theorem and every model theorem depends only on Lean's standard axioms. The independent checker \texttt{lean4checker} can be run on the compiled modules as a second, separate verification. This level shows that each theorem follows from its hypotheses; whether a statement says what the paper claims must be judged by reading it, for which \sref{stmts} gives every statement in mathematical notation, and whether its hypotheses hold for a numerical result is stated in Supplementary Table~\ref{tab:scope}. It takes about 20~minutes on a many-core machine and one to two hours on a laptop (most of it for the largest models, Chen and Froehlich), and needs only the Lean version manager \texttt{elan}, which installs Lean~4.23.0 and the precompiled Mathlib.

\emph{Level C: do the analyses, re-run from the original benchmark problems, give the stored results?} After downloading the PEtab problems (\texttt{scripts/get\_benchmark.sh}, commit \texttt{fcbddf1}), the programs of \texttt{analysis/} are run in the order given in the README, writing to a separate folder (variable \texttt{REPRO\_RESULTS}), and \texttt{scripts/compare\_results.py} compares the new results with the stored ones; the analyses added in the second review are run by \texttt{scripts/fase\_a\_audit2.sh} and \texttt{scripts/identificabilidad\_audit2.sh}. With the fixed seeds the results are deterministic; small differences can arise only where a simulation fails to integrate in one run and not in another (some scenarios of Chen and Isensee) and from different versions of the numerical libraries; for example, the selection of Lang and Raimundez gave the same subsets with libRoadRunner 2.9.2 and 2.10.0, with $e_{\mathrm{fit}}$ agreeing to within $10^{-8}$ (\sref{scen}). This level shows that the stored results are those that the code produces from the public data. Its cost depends on how much is repeated: the method itself (selection of all 34 problems) takes minutes per problem, and about 1.3~h of processor time in total, whereas all the analyses of the paper together took about 673~h of processor time (\sref{time}), that is, about a week on four cores or about a day on a 32-core server. A reader can therefore repeat the selection of every problem, or all analyses of a few problems, on a laptop, while repeating everything for the largest problems (Chen, Isensee, Raimundez, Smith, Bachmann) needs a many-core server. It needs Python with the packages of \texttt{requirements.txt} and the benchmark (about 80~MB).

\subsection*{What each check of the formal verification establishes}
\begin{itemize}\itemsep0pt
\item \emph{Compilation} establishes that every proof is accepted by the Lean kernel, i.e.\ that each theorem follows from its hypotheses.
\item \emph{Axiom inspection} (\texttt{\#print axioms}) establishes that no proof relies on an unproved assumption: the only axioms are \texttt{propext}, \texttt{Classical.choice} and \texttt{Quot.sound}, which are part of Lean's standard logic.
\item \emph{The fidelity check} of \sref{models} establishes that the data on which the model checks run (rate laws, stoichiometry, parameter values and initial values) are those of the benchmark models.
\end{itemize}
The statements themselves should be compared with the mathematics they are meant to encode; \sref{stmts} gives each statement in mathematical notation for this purpose.

\subsection*{Versions}
Lean~4.23.0 (file \texttt{lean\_proofs/lean-toolchain}) and Mathlib at tag \texttt{v4.23.0} (file \texttt{lean\_proofs/lakefile.lean}). The Python programs use Python~3.11 with libRoadRunner~2.10, libSBML~5.21, NumPy, SciPy, pandas, SymPy and Matplotlib at the versions listed in \texttt{requirements.txt}.

\subsection*{Steps for the formal verification}
\begin{enumerate}\itemsep0pt
\item Install the Lean version manager \texttt{elan} (\url{https://github.com/leanprover/elan}); it reads the Lean version from \texttt{lean-toolchain}.
\item In the folder \texttt{lean\_proofs/}, run \texttt{./verify.sh}. The script (i) checks that no file contains \texttt{sorry} or an \texttt{axiom} declaration, (ii) downloads the precompiled Mathlib (\texttt{lake exe cache get}), (iii) compiles the 32 theory modules, the witnesses \texttt{NonVacuity.lean} and the 28 models (\texttt{lake build}) and (iv) prints the axioms of every theorem (\texttt{CheckAxioms.lean}) and of the final theorem of every model (\texttt{CheckModelAxioms.lean}). The theory compiles in a few minutes; the models take longer, the largest (Chen and Froehlich) about 30 minutes each. A large stack is needed (\texttt{ulimit -s unlimited}; the build passes \texttt{--tstack=4000000} to the model files).
\item To inspect one model only: \texttt{lake env lean Models/<model>.lean}. The last line of each model file prints the axioms of its final theorem.
\item To locate a theorem: Supplementary Table~\ref{tab:modules} gives the module of every main result, and \texttt{lean\_proofs/FORMULAS.md} lists every declaration with its module and statement; the module \texttt{X} is the file \texttt{lean\_proofs/X.lean}.
\item To check the translation of the models (needs the benchmark): in the folder \texttt{lean\_translation/}, \texttt{python sbml\_to\_lean.py} regenerates the model files from the SBML models (the files are identical to those of \texttt{lean\_proofs/Models/}), \texttt{python verify\_translation.py} compares every model file with its SBML model and writes \texttt{results/sbml\_to\_lean/translation\_fidelity.json}, and \texttt{python mutation\_control.py} shows that a 1\% change of one number of a model file is detected.
\end{enumerate}
Our complete build log, with the compilation time of every module, is \texttt{lean\_proofs/BUILD\_LOG.md}.

\subsection*{First-order re-estimation}
For the eight problems treated to first order, the first-order re-estimation uses the columns of the sensitivity matrix of the selected and of the calibration parameters, $J_{S\cup\Theta_C}$; the program computes the columns of both kinds of parameters. Run from scratch, without any cached result, it reproduces exactly the subsets and $e_{\mathrm{fit}}$ reported for all eight problems (for example Bachmann: CISRNADelay and JAK2ActEpo, $e_{\mathrm{fit}}=0.337$; Chen: k106 and k44, $0.082$).
